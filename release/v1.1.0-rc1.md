# S Pen Bridge v1.1.0-rc1

Release candidate for Linux and Android, with experimental Windows support.
Physical S Pen acceptance and broader compositor/application validation remain
open. This candidate does not establish a maximum end-to-end latency or a fresh
sensor sampling rate.

## Changes since v1.0.0

- Pair Android and desktop using a certificate fingerprint and pairing code.
  Both USB and Wi-Fi use pinned TLS and authenticated protocol v2. The desktop
  listens on loopback by default; Wi-Fi access requires an explicit opt-in.
- USB uses `adb reverse`, automatically restores its tunnel after reconnects,
  and tries USB before the configured Wi-Fi fallback.
- Input sessions have bounded queues, single-client ownership and safer
  disconnect/reset handling. Heartbeat replies no longer block the input writer.
- Android provides a blank pen surface, controls that hide during pen proximity,
  a live tablet-area editor and simpler settings with independent local saves.
- Desktop settings adapt to smaller windows and larger text. Fresh installs
  start with a neutral Default profile; existing profiles are preserved.
- Experimental Windows Ink support includes a VHF driver source, build pipeline
  and installation/validation tools. Production-signed Windows binaries are
  not included.

## Installation and upgrade

Use the desktop source and Android APK from **this same release**. The old
v1.0.0 Android app uses an incompatible protocol and cannot pair with this server.

Linux: unpack the source archive or check out `v1.1.0-rc1`, then use the manual
installation steps in `README.md` (`server/setup_uinput.sh`, virtual environment,
and pinned Python requirements) and launch `./start.sh`. The one-command
installer follows the default branch rather than pinning this candidate.
See `docs/SETUP.md` and `docs/PAIRING.md`.

Android: verify `SHA256SUMS`, then sideload
`spen-bridge-android-v1.1.0-rc1.apk`. This is a release build signed with the
dedicated S Pen Bridge release certificate; its public certificate and SHA-256
fingerprint are included in the repository under `release/`.

**Existing debug installations need a migration:** v1.0.0 was signed with a
different debug certificate. Android will reject an in-place update signed by
the new release key. Record your tablet-area/input preferences, uninstall the
old app, and install this APK. Uninstalling removes app-private settings and
pairing; pair again afterward. New releases using this dedicated key can update
this candidate in place. Keep a working older setup until you are ready to migrate.

## Known limitations

- Physical hover/contact/lift, palm and edge/firmware behavior still need final
  acceptance. Injected events and native layout/accessibility checks are not
  proof of physical EMR behavior.
- Neither a 300 µs maximum end-to-end latency nor 1,000 fresh sensor samples/sec
  has been demonstrated. Synthetic transport capacity results are separate.
- Queue freshness is local to Android. Delayed authenticated input can still
  arrive after spending time in TCP/TLS; no end-to-end freshness guarantee is made.
- Windows remains experimental: production driver signing, installation,
  Windows Ink, PnP and sleep/resume validation remain open on Windows hardware.
- Direct accessory USB is a debug-only experiment, not a production transport.

See `docs/UI_UX_REMAINING_WORK.md`, `docs/LATENCY_IMPLEMENTATION_STATUS.md`
and `docs/WINDOWS.md` for the verification boundaries.
